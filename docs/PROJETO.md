## 5. ESTRUTURA DO REPOSITÓRIO

Criar uma organização profissional contendo:

- `skills/` — Skills divididas por categorias
- `catalog/` — catálogo e inventário
- `templates/` — modelos reutilizáveis
- `scripts/` — ferramentas de validação e manutenção
- `tests/` — testes das Skills e do catálogo
- `docs/` — documentação com MkDocs
- `examples/` — exemplos práticos
- `README.md` — apresentação do projeto
- `CONTRIBUTING.md` — contribuição
- `CHANGELOG.md` — histórico de alterações
- `LICENSE` — licença a definir
- `.github/workflows/` — validações automáticas

Cada Skill deverá ter um arquivo `SKILL.md` válido e, quando necessário, scripts, exemplos, testes e referências próprias.

## 6. PADRÃO DE QUALIDADE

Cada Skill deverá conter:

- Nome e descrição
- Objetivo e situações de uso
- Pré-requisitos
- Instruções técnicas claras
- Boas práticas profissionais
- Restrições de segurança
- Exemplos práticos
- Testes ou critérios de validação
- Referências oficiais
- Compatibilidade com agentes
- Versão e histórico de alterações

Evitar Skills genéricas, repetidas, inseguras ou que prometam funcionalidades inexistentes.

## 7. SISTEMA DE ACOMPANHAMENTO

Criar um catálogo com as seguintes colunas:

Criar indicadores para saber quantas Skills estão planejadas, em andamento, testadas e concluídas.
